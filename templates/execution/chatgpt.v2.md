# How to carry out research run {{RUN_ID}} (ChatGPT)

These notes are for ChatGPT only. The research prompt for this run is the same, byte for byte, for every model: {{PROMPT_VERSION}}, SHA-256 {{PROMPT_SHA256}}, holding period {{HORIZON_START}} to {{HORIZON_END}}. These notes change nothing in it. Where they seem to differ from the prompt, the prompt decides.

1. **One project, then its receipt.** This run is one project. Read the complete prompt first, including the grading appendix and its JSON skeleton; if it is cut off or the skeleton is missing, fetch it again with get_research for this run ID, never from memory or another run. Research independently: do not look for or use Claude's or Gemini's reports, grades or conclusions. Finish with one save_report and report its receipt (status and report ID) to Eric before starting any other project.
2. **Retrieve primary sources before you grade.** Open, and cite with dates: the implementation files that power the product, at a named commit; evidence of product use; the token's economics and the supply that enters during the holding period; dated team, ownership, control and security developments; and market data you can actually use for the chart and for liquidity. Commit counts, stars or an audit badge are not code quality; a listing on a venue is not executable liquidity; intuition is not a probability.
3. **When an important source fails, try once more, then say so.** Make one bounded alternative attempt (another official route, a mirror, a block explorer, another venue's data) and state plainly what stayed unavailable and which grades that limits. Use the history the project actually has: a token launched last month has a month of data, and that is a disclosure, not a failure.
4. **Each judgment on its own evidence.** For every investment component and category grade, give the evidence it rests on (its own claim and source IDs, not one shared list), its main weakness, the assumptions you used (for example a small spot position on venues a US person can use, when the owner's exact size is not stated) and the reason for the number. Where a related category grade is unknown but you score a component, say which narrower evidence and assumptions support the component.
5. **A point where the evidence supports one; a range only between two named readings; otherwise unknown.** Give a range only when its low and high ends are two named interpretations the evidence supports, and say what observable fact would tell them apart. A range is your judgment, not a statistical confidence interval; never present it as one. Where the evidence is insufficient, the score is unknown, with what is missing and what would settle it. Never turn an unknown into a band, and never fill in a number to complete the form.
6. **Chart and liquidity, or their limits.** For the chart reading, name the data source, venue, pair, timeframes and the date of the latest candle; the trend against USD and against BTC; the volume baseline you compared against; and the levels you observed. If you could not get usable data, say exactly what is missing and leave the dependent grades unknown.
7. **Check the JSON block against the frozen schema and your report.** Every score, range and unknown matches what the report concludes; every categorical word is one the appendix allows (for example catalyst kind and status, source types, confidence, the chart phase); every evidence reference points to a listed claim or source; the run ID, project, prompt version, rubric, scoring profile and holding period are this run's, copied from the prompt. The desk refuses a report that names another run or contract.
8. **A withheld grade is an acceptable result.** An unknown component withholds the dashboard's grade; that is honest, not a defect. Save again only to correct a documented issue (the JSON block misstates your written report) or to record a clearly explained revision, and then pass revision with its kind and a sentence on what changed and why. New facts in a revision need the new sources they rest on.
